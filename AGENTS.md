## Working agreements

- **Vocabulary is binding.** Use the preferred term from [CONTEXT.md](CONTEXT.md)
  in code, comments, UI strings, commit messages, and docs. When you introduce a
  genuinely new domain concept, add it to CONTEXT.md in the same change — including
  the `_Avoid_:` line. Do not restate the glossary in other files; link to it.
- **Decisions get an ADR.** Anything hard to reverse (a format, a namespace, a
  threading choice, a dependency) gets a record in `docs/adr/` before or with the
  implementation. Claim the next free number — check
  [the index](docs/adr/README.md) first, because 0046 and 0049 were each briefly
  issued twice. ADRs are append-only: supersede, never rewrite.
- **Logic exists exactly once.** If preview, export, CLI, and thumbnails need the
  same math, they call the same function. The fragment shader is the single source
  of truth for adjustments; the CPU never re-implements it.
- **Touch only what you change.** Never reformat, re-indent, or reorder includes
  in files unrelated to your task. Limit `just format` to the files you actually
  edited — whole-tree formatting passes bloat the diff and obscure the real change.
  A cleanup-only reformat belongs in its own commit.

## Commands

Routine project maintenance lives in the `Justfile`; run `just` to list recipes.
When a recipe needs more than a couple of commands, put the logic in a `tools/*.py`
script (stdlib, argparse, styled like `tools/package_windows.py`) and make the
recipe a thin `uv run tools/<name>.py {{args}}` wrapper — **not** an inline bash
recipe, which isn't portable since the Justfile sets `windows-powershell := true`.
See `bump`, `rpm`, and `windows-installer`.

### Build

The per-platform dependency and configure commands are in
[README.md § Building](README.md#building). The short version once configured:

```bash
cmake -B build -G Ninja -DCMAKE_BUILD_TYPE=Debug
ninja -C build
./build/arraw
```

### Tests

* **Run**: `just test`, or `ctest --test-dir build --output-on-failure`
* Catch2 v3 tests live in `tests/`, linking the `arraw_ui` and `arraw_cli` static
  libraries (all source except the `main.cpp` entry points).
* Fixtures are in `tests/fixtures/`; the DNG is generated by `make_test_dng.py`.
* Strategy, tolerances, and the golden-image policy:
  [DESIGN.md § Testing Strategy](DESIGN.md#testing-strategy) and
  [ADR 0005](docs/adr/0005-golden-image-tests-tolerance-policy.md).
* **`[gpu]` golden tests skip without a GPU** — see the shader warning below.

### Formatting and linting

```bash
just format        # format all C++ source/header files
just format-check  # check without modifying
just clazy         # optional Qt-aware static analysis, requires clazy
just tidy          # optional general static analysis, requires clang-tidy
```

* **Formatter**: `clang-format` 18+ preferred. Keep formatting mechanical.
* **Warnings** are the primary lint baseline — the normal CMake build enables
  `/W4` on MSVC, `-Wall -Wextra -Wpedantic` elsewhere. Do not introduce new
  warnings in touched code.
* **Qt analysis**: `clazy` is optional and advisory. `just clazy` rebuilds the
  application target only with tests disabled, because Catch/test diagnostics are
  noisy and not useful for Qt analysis. Fix clear Qt correctness/performance
  issues, but avoid large style rewrites to satisfy analyzer output.
* **General analysis**: `clang-tidy` is optional and advisory (config in
  `.clang-tidy`). `just tidy` runs it over `src/` using the compile database from
  the normal `build` dir. Checks cover `bugprone/performance/modernize/
  readability`. Address clear bug/perf findings; do not chase every readability nit.
* **Tool overrides**: set `CLANG_FORMAT`, `CLAZY`, `CLANG_TIDY`, or
  `RUN_CLANG_TIDY` if the local binaries are versioned, e.g.
  `CLANG_FORMAT=clang-format-18 just format-check`.

## Shaders

Shaders are Vulkan-dialect GLSL in `shaders/`, compiled at build time by `qsb` and
baked into the binary as Qt resources (`:/shaders/*.qsb`). Modifying them requires
a rebuild. `shaders/image.frag` is the **source of truth for adjustment order** —
[DESIGN.md § Processing Pipeline](DESIGN.md#processing-pipeline-full-order)
documents that order and must be updated alongside it.

> **The uniform block `buf` must be declared identically in three places:
> `image.vert`, `image.frag`, and the `Ubuf` struct in `RendererCore.h` — same
> fields, same order, same std140 layout, byte-for-byte.**

This holds even for a field a stage never reads: the OpenGL RHI backend links the
vertex and fragment stages into one program, and *any* divergence in the shared
block makes linking fail at runtime with:

```
Failed to link shader program: error: uniform 'u' declared as type 'buf' and type 'buf'
```

When that happens the viewport shader never loads, so the **image area renders
black** (often with stale, vertically-flipped framebuffer contents showing through)
while the rest of the Qt widget UI looks fine. The headless golden-render tests are
skipped without a GPU, so the test suite will **not** catch this — after any change
to the uniform block, do a manual GPU smoke-run (launch the app, confirm the
viewport renders) and watch stderr for the link error. When adding a field, add it
to all three declarations in the same change, even if only one stage uses it.

### Adding a new adjustment

Requires updating, in one change: `GlobalAdjustment` (the struct), the control in
`AdjustmentPanel`, the uniform block in **both** `image.vert` **and** `image.frag`,
the `Ubuf` mirror in `RendererCore.h` (std140 layout must match exactly),
`RendererCore::fillUbuf()`, `XmpSidecar` load/save, and the owning
[Develop Group](CONTEXT.md) in `DevelopGroup.cpp` so the field travels with
copy/paste and presets.

Slider scale conventions (`AdjustmentPanel` uses integer `QSlider`s):

* `exposure`: slider × 0.01 = EV (range -500..500 → -5.0..5.0 EV)
* `temperature`: slider value = Kelvin directly (2000..12000)
* All other fields: slider value = float value directly

## Diagnostics

Set `ARRAW_TRACE` to print per-operation timings (`[trace] <label> N ms` on stderr)
for expensive work — RAW load stages, the standard image loader, and the lcms
colour transforms. The facility is `src/core/Trace.h` (`trace::Scope` for a whole
scope, `trace::Laps` for multi-stage ops); it costs nothing when the variable is
unset.

On Windows `arraw-gui.exe` (the editor) is a GUI-subsystem binary with no attached
console, so redirect to capture it: `arraw-gui.exe 2> trace.txt`. `arraw.exe` (the
console front-end) attaches a console normally.

To see which GPU adapter Qt selected, run with
`QT_LOGGING_RULES="qt.rhi.general=true"` — see [docs/faq.md](docs/faq.md).

## Code style

Full rules: [docs/code_guidelines.md](docs/code_guidelines.md). The two that get
violated most:

* **No Hungarian notation, no `m_` prefixes.** The legacy code has `m_`; when you
  edit a file, **strip the `m_` prefixes in it** and never introduce new ones.
* **Modern C++20**, `const` by default, `auto` where the type is obvious.

## UI theme and colours

* The neutral dark theme is applied once in `main()` via `Theme::apply()` (Fusion
  style + a dark `QPalette`), **before** any widget is constructed. Dark-only for
  now; the palette is built in one function so a light variant slots in behind the
  same seam ([ADR 0031](docs/adr/0031-neutral-dark-fusion-theme.md)).
* **All UI chrome colours are single-sourced in `src/core/ThemeColors.h`** (a
  dependency-free leaf header), read by both `Theme` (the palette) and
  `RendererCore` (the viewport surround, `kCanvas`). Add or change a chrome colour
  *there*, not inline.
* `kCanvas` is part of the golden-image references
  ([ADR 0005](docs/adr/0005-golden-image-tests-tolerance-policy.md)); changing it
  requires regenerating them.
* **Semantic / data-viz colours stay hardcoded with their feature** (histogram
  channels, filmstrip flags/ratings, curve channel buttons, viewport overlays and
  clipping warnings) — they encode meaning, not chrome, so don't route them through
  the theme.
* Prefer the palette over QSS. Any QSS stays minimal and centralized in
  `Theme::apply()`; the per-widget sheet on the `AdjustmentPanel` curve buttons is
  the one sanctioned exception (semantic colours).
